# Витрина отелей для командировок

Сервис на PHP 8.4. ReactPHP ведёт входящие HTTP-запросы и запросы к поставщику в одном цикле событий. Каталог хранится в SQLite в памяти процесса.

## Запуск

Из корня проекта:

```sh
docker build -t hotels .
docker run --rm -p 8000:8000 \
  --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --cap-drop ALL --user 1000:1000 \
  --memory 256m --memory-swap 256m --cpus 0.5 --pids-limit 64 \
  hotels
```

```sh
curl http://localhost:8000/health
curl -X POST http://localhost:8000/supplier/source \
  -H 'Content-Type: application/json' \
  -d '{"url":"http://supplier.internal:9000"}'
curl -X POST http://localhost:8000/import \
  -H 'Content-Type: application/json' \
  -d '{"hotels":[{"id":"h-0000123","name":"Исеть","city":"SVX","price":"5400.55"}]}'
curl -i http://localhost:8000/hotels/h-0000123
curl 'http://localhost:8000/hotels?city=SVX&max_price=600000'
```

## Как работает служба

- **Полная выгрузка.** Сначала проверяется структура JSON. Записи проверяются и записываются партиями во временную таблицу в памяти. Между партиями сервер продолжает отвечать. Пока импорт идёт, поиск видит предыдущий каталог. Готовая таблица целиком становится активной. Повторяющиеся идентификаторы заменяются последней валидной записью. Договорные отели хранятся в отдельной таблице.
- **Цена в карточке.** В течение 50 секунд после получения выгрузки или цены от поставщика карточка берётся локально. После этого первый запрос карточки запрашивает свежую цену. Параллельные запросы того же отеля ждут один исходящий запрос. Тайм-аут поставщика составляет 850 мс. При сбое показывается последняя известная цена, а без неё возвращается 503. После 503 поставщика исходящие запросы к нему приостанавливаются на время из Retry-After.
- **Удаление.** Ручное удаление отеля поставщика блокирует карточку и поиск до выгрузки с этим идентификатором. Ответ HOTEL_NOT_FOUND убирает отель из поиска и отдаёт 404. Следующий запрос карточки сможет снова обратиться к поставщику.
- **Поиск.** Индексы по городу, цене и идентификатору позволяют получать страницу в заданном порядке. Цены переводятся в копейки целочисленно, до сортировки и фильтрации.
- **Счётчики.** Успешные GET карточки увеличивают один из счётчиков served_local и served_from_supplier. Если запрос к поставщику завершился сбоем, но карточка отдана с запасной ценой, её заголовок X-Source равен SUPPLIER. supplier_requests считает отдельные исходящие запросы, включая сбои.

## Интеграционная проверка

Скрипт tests/smoke.mjs запускает имитацию поставщика на порту 9000 и отправляет HTTP-запросы в уже работающую витрину. Для проверки нужен отдельный экземпляр витрины, поскольку скрипт заменяет содержимое каталога. Скрипту нужен Node.js 20 или новее. Проверка занимает примерно минуту из-за ожидания истечения кэша.

Если витрина и скрипт работают на одном хосте:

```sh
node tests/smoke.mjs
```

Для Docker Desktop запустите витрину как в примере выше и укажите адрес хоста для запросов из контейнера:

```sh
SUPPLIER_URL=http://host.docker.internal:9000 node tests/smoke.mjs
```

В PowerShell установите переменную командой $env:SUPPLIER_URL = 'http://host.docker.internal:9000'. На Linux для этого адреса добавьте к docker run параметр --add-host=host.docker.internal:host-gateway.
